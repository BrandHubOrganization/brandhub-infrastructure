Cross-DB Reference Strategy (business-service)
MongoDB (tasks)
tasks {
workspaceId: string // FK to PG
}
Soft reference
No FK constraint
Application-level join
in-memory after 2 queries
PostgreSQL (workspaces)
workspaces {
id: UUID (PK)
agencyId: UUID (FK)
}
Rule: business-service queries MongoDB và PostgreSQL riêng biệt, sau đó join trong application memory. Không thực hiện JOIN trực tiếp ở DB engine level giữa 2 loại DB. Mọi document Mongo tham chiếu tới entity PostgreSQL (workspace, agency, client_profile...) chỉ bằng ID string — không có ràng buộc FK thật. Bên trong PostgreSQL, FK vẫn dùng bình thường (vd: workspaces.agency_id → agencies.id). Đây là cách duy nhất cross-DB reference được phép trong hệ thống — ai-service và publisher-service không được biết về cấu trúc này.
business-service
Sole owner của PostgreSQL (23 bảng), 14 MongoDB collection nghiệp vụ, và Redis. Mọi CRUD đều qua service này. ai-service và publisher-service không được kết nối trực tiếp vào bất kỳ DB nào trong nhóm này.
ai-service
Sole owner của ChromaDB, ghi vào S3, và 2 MongoDB collection (knowledge_documents, ai_usage_logs). Không bao giờ kết nối PostgreSQL hay MongoDB business collections. Lấy business context (Workspace/Agency/brand info) qua REST API từ business-service khi cần.
publisher-service
Chỉ sở hữu 1 collection riêng (publish_logs). Toàn bộ data cần để publish (nội dung + token + config) được đóng gói trong RabbitMQ message bởi business-service trước khi enqueue. Sau publish gửi callback HTTP.
