# DA-E07-04 — Standard API Response Format

**Sprint:** 3 | **Owner:** Trung (Leader) | **Priority:** 🔴 Critical  
**Blocks:** DA-E07-05, DA-E07-06  
**Blocked by:** DA-E07-01

## 1. Overview

Every HTTP response from `business-service` and `ai-service` **must** use the `ApiResponse<T>` envelope. No endpoint may return a bare object, bare array, or plain string body.

The `api-gateway` also wraps its own error responses (rate limit, auth failure) in this same format so the frontend has one single parsing contract across all services.

---

## 2. ApiResponse\<T\> Schema

### 2.1 Full schema

```json
{
  "success":   "boolean",
  "data":      "T | null",
  "error":     "ErrorBody | null",
  "meta":      "MetaBody | null",
  "requestId": "string (UUID v4)",
  "version":   "string",
  "timestamp": "string (ISO8601 UTC)"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `success` | `boolean` | Always | `true` on 2xx; `false` on 4xx/5xx |
| `data` | `T \| null` | Always | Payload on success; `null` on error |
| `error` | `ErrorBody \| null` | Always | `null` on success; error detail on failure |
| `meta` | `MetaBody \| null` | Optional | Pagination info — present when `data` is a page |
| `requestId` | `string` | Always | UUID v4 generated by api-gateway on request entry, injected as `X-Request-Id` header, echoed in response — use for log correlation across all services |
| `version` | `string` | Always | API version string — currently `"v1"`. Frontend uses this to select the correct response parser when multiple API versions are live |
| `timestamp` | `string` | Always | Server time when response was generated (ISO8601 UTC) |

### 2.2 ErrorBody schema

```json
{
  "code":    "string",
  "message": "string",
  "details": "object | null"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `code` | `string` | Machine-readable error code from catalogue (§4) |
| `message` | `string` | Human-readable description — English in MVP; i18n key in future |
| `details` | `object \| null` | Extra context — field validation errors, conflicting resource id, etc. |

### 2.3 MetaBody schema (pagination)

```json
{
  "page":  "number (1-based)",
  "size":  "number",
  "total": "number (total matching records)"
}
```

When `meta` is present, `data` is always an array (`T[]`).

## 3. HTTP Status Code → Response Shape

### 3.1 Standard mapping

| HTTP Status | `success` | `data` | `error` | When used |
|-------------|-----------|--------|---------|-----------|
| `200 OK` | `true` | payload | `null` | Successful read or update |
| `201 Created` | `true` | created resource | `null` | Resource created |
| `202 Accepted` | `true` | job stub `{ jobId, status }` | `null` | Async job queued (report gen) |
| `204 No Content` | — | — | — | **Never used** — always return 200 with `{ "success": true, "data": null }` instead (keeps parser consistent) |
| `400 Bad Request` | `false` | `null` | ErrorBody | Validation failure, invalid state transition, business rule violation |
| `401 Unauthorized` | `false` | `null` | ErrorBody | Missing or invalid JWT; invalid/expired refresh token |
| `403 Forbidden` | `false` | `null` | ErrorBody | Valid JWT but insufficient role/permissions |
| `404 Not Found` | `false` | `null` | ErrorBody | Resource not found; or resource exists but caller cannot access it (use 404 over 403 when hiding existence) |
| `409 Conflict` | `false` | `null` | ErrorBody | Duplicate resource (email, slug); state conflict |
| `422 Unprocessable Entity` | `false` | `null` | ErrorBody | Syntactically valid request but semantically invalid (reserved for future use; prefer `400` in MVP) |
| `429 Too Many Requests` | `false` | `null` | ErrorBody | Rate limit exceeded — returned by **api-gateway**, not business-service |
| `500 Internal Server Error` | `false` | `null` | ErrorBody | Unhandled server exception |
| `502 Bad Gateway` | `false` | `null` | ErrorBody | Upstream service (AI, Stripe, social platform) unreachable |
| `503 Service Unavailable` | `false` | `null` | ErrorBody | Service starting up or in maintenance mode |

### 3.2 Decision guide: 400 vs 404 vs 409

```
Was the request structurally invalid? (missing field, bad format)
  → 400 VALIDATION_ERROR

Does the resource not exist?
  → 404 {RESOURCE}_NOT_FOUND

Does the resource exist but can't be used in this state?
  → 400 {RESOURCE}_NOT_{STATE}  (e.g. POST_NOT_DRAFT)

Does creating the resource conflict with an existing one?
  → 409 {RESOURCE}_{FIELD}_EXISTS  (e.g. EMAIL_ALREADY_EXISTS)

Does the caller lack permission?
  → 403 FORBIDDEN
  → or 404 {RESOURCE}_NOT_FOUND if hiding existence is preferred
```

## 4. Error Code Catalogue

Format: `SCREAMING_SNAKE_CASE`. All codes globally unique across all services.

### 4.1 Auth domain — `AUTH_*`

| Code | HTTP | Trigger |
|------|------|---------|
| `EMAIL_ALREADY_EXISTS` | 409 | Register with existing email |
| `INVALID_CREDENTIALS` | 401 | Login — wrong email or password |
| `ACCOUNT_SUSPENDED` | 403 | Login — user `status = SUSPENDED` |
| `REFRESH_TOKEN_INVALID` | 401 | Refresh — token not found, expired, or revoked |
| `REFRESH_TOKEN_BLACKLISTED` | 401 | Refresh — jti in Redis blacklist |
| `RESET_TOKEN_INVALID` | 400 | Reset-password — token not in Redis |
| `RESET_TOKEN_USED` | 400 | Reset-password — `used_at` already set |
| `OAUTH_STATE_INVALID` | 400 | OAuth callback — state not in Redis (CSRF) |
| `OAUTH_CODE_INVALID` | 400 | OAuth callback — platform token exchange failed |
| `INVALID_REDIRECT_URI` | 400 | OAuth initiation — URI not in allowlist |

## 6. Implementation Contracts

### 6.1 business-service (Java / Spring Boot)

**Java record:**

```java
public record ApiResponse<T>(
    boolean success,
    T data,
    ErrorBody error,
    MetaBody meta,
    String requestId,
    String version,
    Instant timestamp
) {
    private static final String API_VERSION = "v1";

    public static <T> ApiResponse<T> ok(T data, String requestId) {
        return new ApiResponse<>(true, data, null, null, requestId, API_VERSION, Instant.now());
    }

    public static <T> ApiResponse<T> ok(T data, MetaBody meta, String requestId) {
        return new ApiResponse<>(true, data, null, meta, requestId, API_VERSION, Instant.now());
    }

    public static ApiResponse<Void> noContent(String requestId) {
        return new ApiResponse<>(true, null, null, null, requestId, API_VERSION, Instant.now());
    }

    public static ApiResponse<Void> error(String code, String message, String requestId) {
        return new ApiResponse<>(false, null, new ErrorBody(code, message, null), null, requestId, API_VERSION, Instant.now());
    }

    public static ApiResponse<Void> error(String code, String message, Object details, String requestId) {
        return new ApiResponse<>(false, null, new ErrorBody(code, message, details), null, requestId, API_VERSION, Instant.now());
    }
}

public record ErrorBody(String code, String message, Object details) {}

public record MetaBody(int page, int size, long total) {}
```

**RequestId resolution — read from gateway-injected header:**

```java
// In each controller or via HandlerMethodArgumentResolver:
@GetMapping("/posts")
public ResponseEntity<ApiResponse<List<PostDto>>> listPosts(
        @RequestHeader("X-Request-Id") String requestId,
        ...) {
    var posts = postService.list(...);
    return ResponseEntity.ok(ApiResponse.ok(posts, meta, requestId));
}

// Or centralize via filter — store requestId in request-scoped bean:
@Component
public class RequestIdFilter implements Filter {
    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain) {
        String requestId = ((HttpServletRequest) req).getHeader("X-Request-Id");
        if (requestId == null) requestId = UUID.randomUUID().toString(); // fallback
        RequestContext.setRequestId(requestId);
        chain.doFilter(req, res);
    }
}
```

**Global exception handler:**

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ApiResponse<Void>> handleBusiness(BusinessException ex) {
        return ResponseEntity
            .status(ex.getHttpStatus())
            .body(ApiResponse.error(ex.getCode(), ex.getMessage(), ex.getDetails()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiResponse<Void>> handleValidation(MethodArgumentNotValidException ex) {
        Map<String, String> fields = ex.getBindingResult().getFieldErrors().stream()
            .collect(Collectors.toMap(FieldError::getField, FieldError::getDefaultMessage));
        return ResponseEntity
            .status(400)
            .body(ApiResponse.error("VALIDATION_ERROR", "Request validation failed",
                Map.of("fields", fields)));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<Void>> handleGeneric(Exception ex) {
        log.error("Unhandled exception", ex);
        return ResponseEntity
            .status(500)
            .body(ApiResponse.error("INTERNAL_ERROR", "An unexpected error occurred. Please try again later."));
    }
}
```

### 6.2 ai-service (Python / FastAPI)

**Pydantic model:**

```python
from pydantic import BaseModel, Field
from typing import Generic, TypeVar, Optional, Any
from datetime import datetime, timezone

T = TypeVar("T")

API_VERSION = "v1"

class ErrorBody(BaseModel):
    code: str
    message: str
    details: Optional[Any] = None

class MetaBody(BaseModel):
    page: int
    size: int
    total: int

class ApiResponse(BaseModel, Generic[T]):
    success: bool
    data: Optional[T] = None
    error: Optional[ErrorBody] = None
    meta: Optional[MetaBody] = None
    request_id: Optional[str] = Field(None, alias="requestId")
    version: str = API_VERSION
    timestamp: str = ""

    model_config = {"populate_by_name": True}

    def model_post_init(self, __context):
        if not self.timestamp:
            self.timestamp = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")

    @classmethod
    def ok(cls, data: T, request_id: str = None, meta: Optional[MetaBody] = None) -> "ApiResponse[T]":
        return cls(success=True, data=data, meta=meta, requestId=request_id)

    @classmethod
    def no_content(cls, request_id: str = None) -> "ApiResponse[None]":
        return cls(success=True, requestId=request_id)

    @classmethod
    def error(cls, code: str, message: str, details=None, request_id: str = None) -> "ApiResponse[None]":
        return cls(
            success=False,
            error=ErrorBody(code=code, message=message, details=details),
            requestId=request_id
        )
```

**FastAPI global exception handler:**

```python
from fastapi import Request
from fastapi.responses import JSONResponse
from fastapi.exceptions import RequestValidationError

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    fields = {e["loc"][-1]: e["msg"] for e in exc.errors()}
    return JSONResponse(
        status_code=400,
        content=ApiResponse.error(
            code="VALIDATION_ERROR",
            message="Request validation failed",
            details={"fields": fields}
        ).model_dump()
    )

@app.exception_handler(BusinessException)
async def business_exception_handler(request: Request, exc: BusinessException):
    return JSONResponse(
        status_code=exc.http_status,
        content=ApiResponse.error(
            code=exc.code,
            message=exc.message,
            details=exc.details
        ).model_dump()
    )

@app.exception_handler(Exception)
async def generic_exception_handler(request: Request, exc: Exception):
    logger.exception("Unhandled exception")
    return JSONResponse(
        status_code=500,
        content=ApiResponse.error(
            code="INTERNAL_ERROR",
            message="An unexpected error occurred. Please try again later."
        ).model_dump()
    )
```

### 6.3 api-gateway (Node.js / Express or Spring Cloud Gateway)

Gateway wraps its own errors in the same envelope:

```javascript
// Express middleware example
function gatewayErrorHandler(err, req, res, next) {
  const timestamp = new Date().toISOString();
  
  if (err.type === 'RATE_LIMIT') {
    return res.status(429).json({
      success: false,
      data: null,
      error: {
        code: 'RATE_LIMIT_EXCEEDED',
        message: 'Too many requests. Please slow down.',
        details: { retryAfterSeconds: err.retryAfter }
      },
      meta: null,
      timestamp
    });
  }

  if (err.type === 'JWT_ERROR') {
    return res.status(401).json({
      success: false,
      data: null,
      error: { code: err.code, message: err.message, details: null },
      meta: null,
      timestamp
    });
  }
}
```

## 7. Rules & Constraints

### 7.1 What MUST be true (enforceable in code review)

1. **Every controller method returns `ApiResponse<T>`** — never `ResponseEntity<MyDto>` directly
2. **`success` is always the inverse of whether `error` is null** — `success=true` iff `error=null`
3. **`data` is `null` when `success=false`** — never put partial data in error responses
4. **Stack traces never reach the response body** — caught in global handler, logged server-side only
5. **Error `code` comes from the catalogue (§4)** — no ad-hoc string codes in controller logic
6. **`timestamp` is always UTC ISO8601** — `2025-06-15T10:30:00Z` not `2025-06-15T17:30:00+07:00`
7. **Paginated responses always include `meta`** — never return a list without page/size/total
8. **204 is never used** — always return 200 with `data: null` for empty success responses
9. **`requestId` is always populated** — read from `X-Request-Id` header injected by gateway; if missing (direct call bypassing gateway) generate a UUID as fallback — never return `null`
10. **`version` is always `"v1"`** — hardcoded constant in service, not computed — change requires explicit release decision

### 7.2 What the frontend can rely on

- Parse `success` first — no need to check HTTP status
- If `success=false`, `error.code` is always a stable string (won't change between releases)
- `error.message` is human-readable English (display to developer; build i18n lookup from `code` for end-user UI)
- `meta` is always present when `data` is an array with more items than returned
- `timestamp` allows detecting stale cached responses
- `requestId` is always a non-null UUID — log it in the browser console on every error; include in bug reports to support
- `version` tells the frontend which response shape to use when multiple API versions are live simultaneously

### 7.3 Versioning note

`ApiResponse` schema is **frozen for v1**. Adding fields is backwards-compatible (OK). Removing or renaming fields requires a major version bump and coordinated frontend deploy.
