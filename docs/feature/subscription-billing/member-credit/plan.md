## Accounting handoff and setup — 2026-10-20

- Existing DB: review configuration delta 2026-10-19, then accounting delta 2026-10-20; use `psql -v ON_ERROR_STOP=1 -f <reviewed-file>`. Both contain transactions. Fresh DB uses current init only. Mongo is unchanged. No shared DB has been upgraded during this implementation.
- Implemented: atomic reserve/settle/release, locked price, Plan-first allocation, member ceiling, persistent purchased grants, anchored monthly usage and read reporting. Read routes under `/api/v1/agencies/{agencyId}/credit`: Owner `GET /balance`, member `GET /usage/me`, Owner `GET /members/{memberId}/usage`. Reports include only new accounting records, not legacy aggregates.
- Server-only `CreditGrantService.applyPlan(agencyId, subscriptionId, paymentId)` reads plan quota from DB. Paid plans require completed paid transaction owned by Agency Owner, `PLAN:<planName>` reference and payment time within entitlement period. ACTIVE alone is not payment proof. Free plans need no paid transaction.
- Server-only `applyPurchase(agencyId, paymentId)` verifies completed BUY_CREDIT payment, positive paid amount and trusted `CREDIT:<quantity>` order reference. Payment code must construct that reference server-side. Never accept browser-supplied grant quantities. Invoke handoffs within the verified PostgreSQL payment/subscription transaction; no public grant endpoint exists.
- Grants cannot duplicate a transaction across Agencies or issue two full Plan quotas for the same Agency period. Original monthly anchor stays fixed. Monthly aligned periods are supported; annual periods, mid-period upgrade/proration and cross-Agency allocation require separate integration, not an invented full-quota regrant.
- Pending: AI endpoint adapters, durable dispatch/job ownership and result replay, unknown-outcome reconciliation and Payment/Subscription hook calls. Member tracking UI is now implemented in the Web reporting slice above. Returning the same reservation ID does NOT authorize dispatching another provider request. Do not advertise AI financial enforcement before end-to-end integration checks.
- Unknown outcomes stay RESERVED for reconciliation. Server-only settlement uses successful units and original period/price; no automatic timeout refund. Owner bypasses personal ceiling only, never shared balance.

## Setup for the configuration slice

1. Existing PostgreSQL: review and run only `docs/database/migrations/2026-10-19-member-credit-configuration.sql` against the intended database with `psql -v ON_ERROR_STOP=1 -f ...`. The script contains its own transaction. Do not run init or archived migrations on existing data. No database has been upgraded by this code change.
2. Fresh PostgreSQL: current `init-postgres-v2.sql` already creates the same tables; no separate delta replay is needed. Mongo is unchanged.
3. Compile/restart Business. Missing configuration tables return `503 CREDIT_SCHEMA_NOT_READY` on the new APIs, not automatic schema creation. Existing AI/Billing flows are untouched.
4. Owner first GETs `/api/v1/agencies/{agencyId}/credit/policy`; if missing it returns `defaultMemberLimit: null, revision: 0`. PUT with `{ "defaultMemberLimit": <owner-selected amount>, "expectedRevision": 0 }`. Zero is valid, not unlimited. No invented initial amount.
5. Owner GETs `/api/v1/agencies/{agencyId}/credit/members/{userId}/limit` to obtain override revision. PUT the same path with `{ "memberLimit": <chosen amount>, "expectedRevision": <returned revision> }`. No override resolves the current Agency default, then system fallback 10 (`SYSTEM_DEFAULT`); this is a ceiling, not a join-time credit grant. Existing legacy creator limits are not automatically imported.
6. Authenticated users GET `/api/v1/credit/prices`; empty means no configured prices, never free AI. Admin PUTs `/api/v1/admin/credit/prices/CONTENT_GENERATE` with `{ "unitCredits": <admin-selected price>, "enabled": true, "expectedRevision": 0 }`. Subsequent edits use the returned revision. Content/caption/hashtag units are successful requests; image/video units are successful outputs. Generation adapters remain pending; the example image price 3 is not a configured product price.
7. These APIs configure policy only. They do not make AI chargeable yet, allocate Plan credit or complete FR 3.9.5 reporting. Do not advertise financial enforcement until the remaining checklist passes and Subscription supplies authoritative Agency grants. The existing Subscription subscribe endpoint currently activates without verified payment; do not use that as proof of a paid credit grant.
