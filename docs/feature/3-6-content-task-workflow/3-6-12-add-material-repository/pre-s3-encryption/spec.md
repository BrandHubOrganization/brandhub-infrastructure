# Pre-S3 repository encryption
Custody decision: user explicitly selected backend-held keys. Protect content from S3-only/account-console readers; backend operators with the keys remain able to decrypt. No claim of end-to-end/zero-knowledge encryption.
All new repository/staging/client-vault writes must be ciphertext before S3. Existing public avatar/logo storage is out of scope. Use AWS Encryption SDK with AES-256-GCM key commitment and independent per-object data keys; wrapping keys stored only in backend environment/keyring. Preserve original MIME/size accounting and server content validation. Preview/download/version/publisher URLs point to an expiring backend capability, never directly to decryptable S3 data. Support authenticated Range reads and clean bounded temporary plaintext cache. Capabilities restrict object, operation and expiry; no capability logging.
Migration: inventory S3 repository/staging/client-vault objects and versions. Verify full encryption/decryption/hash before replacement, preserve metadata/logical sizes, conditionally replace ETag and verify downloaded ciphertext. Never remove old versions until verified replacement and explicit migration review; report any residual plaintext versions. No key in source, logs, browser, Mongo, or S3. Encrypted backup of old object is permitted only after verification. Configure keyring before enabling writes. Missing/unknown keys must fail closed.
Keep existing plaintext reads only for migration compatibility; encrypted objects never fall back to plaintext. Cloud-side writes and re-encryption apply only to repository content, not images under image/*.
