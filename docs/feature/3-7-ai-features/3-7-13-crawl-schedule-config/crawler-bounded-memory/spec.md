# Bounded crawler memory
Preserve configured source/post/comment limits and output JSON/RabbitMQ contracts. Crawl serially using isolated browser worker processes, 25 posts per batch by default. Parent/API/scheduler remain alive; session credentials travel in stdin only. Persistent feed/result metadata lives on the crawler output volume in SQLite; results are streamed into atomic JSON exports. Comments are spooled per post and retained top-N ranking must match the current likes/date ordering, including late pages. Release response/comment caches between posts. Do not increase container RAM or deploy in this change.
Observe container cgroup memory (fallback host pressure), soft75/hard85 percent defaults. Recycle on batch/soft pressure, interrupt gracefully on hard pressure. Bound retries when pressure prevents progress; preserve durable pending records and report failure/partial instead of completion. Feed collection also flushes records and checks memory; do not silently declare a resource-limited partial feed complete or loop endlessly rescrolling the same posts. Existing legacy JSON checkpoints can be imported.
CLI currently defaults max-comments200 although the Config dataclass defaults0. Keep both unchanged; unlimited mode remains subject to explicit safety/pressure failure rather than silent truncation. Browser subprocess termination/timeout must be confined to the owned worker tree. No session files on disk, no global AI-service restart.
