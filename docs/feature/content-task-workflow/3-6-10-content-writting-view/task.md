- [x] **6. Real-time sync (FE+BE)**: `useTaskContentSync` hook — STOMP client (`@stomp/stompjs`), Yjs `Y.Doc` wired to `CanvasTextEditor`, `TaskContentWebSocketController` persists + broadcasts updates. Browser-verified single-client: type → persisted via WS → reload → content restored correctly from snapshot+operations, in the right order. **Not yet verified with two concurrent browser sessions** (multi-client convergence is implemented per the Yjs/STOMP design but not manually tested end-to-end).
  - **Bug found and fixed during verification**: `appendOperation`'s `count(taskId) + 1` sequence assignment was not atomic — concurrent WS messages for the same Task could compute the same `sequenceNumber`, the loser's INSERT hit the unique constraint and threw, and that update was silently lost (never persisted, never broadcast). A later Yjs struct whose `origin` pointed at the lost one became a permanently unreachable orphan, which looked like "most of what I typed disappeared after reload." Fixed with a per-task `synchronized` lock in `TaskContentServiceImpl.appendOperation`. Also fixed two related client-side bugs found along the way: a stale `caretIndex` closure in `CanvasTextEditor`'s insert/delete handlers (now backed by a ref), and a missing `yDoc.off()` cleanup for the local-update listener in `useTaskContentSync`.
  - Typing fast enough (e.g. scripted `type_text`-style bulk input near-simultaneously) can still drop a keystroke client-side before it reaches the Y.Doc update event — not reproduced with normal human-speed typing in this verification; flagged here rather than silently ignored.
- [x] **12. Automated tests (2026-10-12)**: 47 Vitest + 22 JUnit + 18 Playwright + 31 live-backend integration, all passing — see [test.md](test.md). The live run found three backend defects the mocks hid: (a) the chat feature's global STOMP interceptor blocked `/ws/tasks` entirely (CONNECT needed an `Authorization` header, only chat destinations allowed) — real-time sync was dead; (b) no workspace-membership check on task content SEND/SUBSCRIBE (fixed in parallel upstream via `authorizeTask`); (c) the per-task lock from item 6 sat inside `@Transactional`, so it released before commit and a 120-update burst lost ~half the updates (`@Transactional` removed from `appendOperation`). All fixed and re-verified. The "Bug found and fixed" note under item 6 was therefore only partly true until this fix. - [x] **9. Version History**: REST load/list/restore snapshot implemented (`TaskContentServiceImpl`), `VersionHistorySidebar` UI implemented. Browser-verified: reporting a snapshot via REST makes it appear in the sidebar, and clicking Restore completes without error.
  - **Fixed (2026-10-12)**: (a) *Restore* previously only remounted the editor and appended a snapshot whose `sequenceNumber` collided with the next operation (that edit was dropped on reload). Now `restoreVersion` is read-only and the client applies the old content to the live `Y.Doc` as a normal edit (delete + `applyDelta`), so it persists, broadcasts to other clients, and keeps the log append-only. (b) The versions API now returns `editedBy` / `editedByName` (last editor included in the snapshot) and the sidebar shows it ("who").
  - **Added (2026-10-12)**: (c) per-version *diff* — new `GET .../content/versions/{snapshotId}` returns that version's Yjs state; the sidebar decodes it and shows a word-level diff against the previous version (`contentUtils.diffText`). (d) Snapshots are also reported after 20 s idle and on leaving the page (not only every 200 operations), so short posts get versions; the sidebar refreshes after each report.
- **Lists (AC "bold, italic, list, emoji")**: bullet / numbered buttons in `FormattingToolbar`; implemented as literal text prefixes (`• `, `1. `) so the published text matches what's shown. Enter inside an item continues the list; Enter on an empty item exits it. Known limits: no hanging indent on wrapped lines, inserting mid-list doesn't renumber following items.
- [x] **10. Offline queue** (2026-10-12): edits made while disconnected are queued in memory and persisted in `localStorage`, flushed on reconnect; on reconnect the log is re-read so missed remote updates merge in; reconnect uses a fresh token (E2E-19). Chose localStorage over IndexedDB since queued Yjs updates are small; revisit if long offline sessions are expected.
